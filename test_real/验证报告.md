# 真实棋盘格 → 边缘裁剪 → sfrmat5 流程验证报告

日期：2026-08-15

## 结论摘要

1. **sfrmat5_py.py 端口本身是正确的**：在项目自带的干净样例
   `sfrmat5_dist/Example_Images/Test_edge1.tif` 上输出完全正常
   （MTF50≈0.267，SFR max=1.000，无 NaN，rot≈95.45°）。
   这说明算法移植没有问题。

2. **test_real/downloads/ 下 4 张图不是斜边 ROI，而是完整棋盘格照片**：
   直接把它们喂给 `sfrmat5_rgb` 必然产生 NaN，这是**输入数据不匹配**，
   不是算法 bug。

3. **已构建真实图片完整流程脚本** `test_real/real_sfr_pipeline.py`：
   `真实棋盘格 → findChessboardCorners 角点检测（亚像素） → 边缘中点裁剪
   → sfrmat5_rgb → 有效 SFR/MTF 输出`，并支持保存 .mat。
   保存条件为"完整有效"：无 NaN、MTF 峰值≥0.99、且 MTF 降到 0.5 以下
   （MTF50 可定义），三者缺一即丢弃，保证每个 .mat 都含完整可用的 MTF50。

## 关键发现：失败根因

### left01：棋盘格近乎正交（物理限制）
- 边缘倾斜角仅 **0.8°–1.6°**（远低于 ISO 12233 斜边法要求的 5°–45°）
- 投影分箱 `_project2` 时产生大量零计数 → SFR=NaN
- **这是 ISO 12233 方法的物理要求，不是代码 bug**。参考 MATLAB 源码
  `sfrmat5.m` 中对零计数有同样的警告逻辑。

### left02/03/05：小 patch 内部分行 centroid 异常
- 有效边缘倾斜角 10°–25°（理想范围），成功率高
- 仍有 30%–40% patch 失败：32px 小 patch 内某些行导数总和≈0
  （噪声主导、无干净梯度），centroid 加权平均产生 92/81 等异常值，
  污染 poly5 边缘拟合 → 分箱零计数 → NaN。
- 这是**小 ROI 测量的固有噪声问题**，增大 patch 会引入相邻棋盘格边
  （更糟），缩小则信号不足，存在尺寸权衡。

## 如何复现

```bash
# 处理全部下载图，保存有效 .mat 到 test_real/out/
python test_real/real_sfr_pipeline.py --save test_real/out

# 自定义有效性判定阈值（默认值如上）
python test_real/real_sfr_pipeline.py --save out/ \
    --min-mtf 0.99       # 条件① MTF 峰值阈值
    --mtf50-level 0.5    # 条件③ MTF 需降到 ≤ 该值
    --tilt-min 5         # 斜边最小倾斜角（度）
    --patch-frac 0.35    # patch 半宽 = frac × 方格尺寸
    --npol 5             # sfrmat5 边缘拟合阶数

# 指定单张图
python test_real/real_sfr_pipeline.py test_real/downloads/left05.jpg --save out/
```

依赖：numpy, opencv-python, scipy。

## 下一步建议

- 若需提升 left02/03/05 通过率：对失败 patch 做中值滤波、或用更大
  patch 配合边缘 ROI 精裁（先粗测边缘位置再放大裁）。
- left01 这类近乎正交的棋盘格应**重新拍摄**（让棋盘格相对相机旋转
  5°–15°），或改用非斜边法（如 ISO 12233 的 knife-edge / Siemens star）。
